# Dota 绝活英雄筛选方案（合并版）

日期：2026-10-21。来源：Codex 方案 `docs/dota-signature-heroes.md` 与 Claude 讨论合并。
状态：讨论方案，第一版已在 DotaHub「绝活」页实现（见 `docs/dotahub.md` 的「绝活」一节），所有参数均未经真实玩家数据校准。

## 0. 给实现者的说明

- 先读 `CLAUDE.md`、`docs/dotahub.md`、现有 `src/lib/dota/` 与 DotaHub 页面，优先复用现有数据链路，不另建重复抓取流程。
- 本文是产品与算法方案，不代表已授权全面实现、变更数据库或发布。
- **第一步是盘点数据字段，不是写算法。** 精通型路径能否启用取决于第 1 节的字段盘点结果。
- 文中数值都是待校准的起始参数，集中放在配置里（见第 10 节），不要散落在实现中，也不要描述为已验证标准。

### 相对 Codex 原版的主要改动

1. 精通型路径明确了外部基准的优先级：Stratz IMP 优先，OpenDota benchmarks 备选，都没有才降级为「高熟练候选」。
2. 说明了天梯匹配会把胜率压向 50%，因此优势型阈值改用概率判断，并且精通型不能只靠胜率成立。
3. 验证在人工标注之外，新增可自动运行的时间外验证。
4. 新增可选的学习期剔除、多重比较提醒、英雄重做处理，以及第二版扩展项。

## 1. 数据范围与字段盘点

### 1.1 比较原则

- 尽量比较同一时期、同一模式、相近分段的数据。
- 只用天梯与普通全英雄选择等正式模式；加速模式、自定义、技能征召等娱乐模式分开统计或排除。
- 有位置数据时，分析单位为「英雄 × 位置」；没有时退化为「英雄」。同一英雄打 1 号位和 4 号位应视为不同条目。

### 1.2 字段盘点清单（实现前先填）

| 数据                                        | 用途                   | 重要性 | 可能来源（以实际接口为准）   |
| ------------------------------------------- | ---------------------- | ------ | ---------------------------- |
| 比赛 ID、英雄、开始时间、胜负               | 基础统计               | 必需   | OpenDota 玩家比赛列表        |
| 游戏模式、大厅类型                          | 模式过滤               | 必需   | OpenDota                     |
| 位置 / 分路角色                             | 按位置拆分、精通型基准 | 增强   | OpenDota（部分比赛）、Stratz |
| 分段 / rank tier                            | 同分段比较             | 增强   | OpenDota、Stratz             |
| 组排人数                                    | 组排拆分               | 增强   | OpenDota、Stratz             |
| 单场表现评分 IMP                            | **精通型首选基准**     | 关键   | Stratz                       |
| benchmarks 百分位（GPM、XPM、补刀、伤害等） | 精通型备选基准         | 备选   | OpenDota，仅限已解析比赛     |
| 同分段英雄胜率                              | 版本修正               | 增强   | OpenDota hero stats          |

盘点结果需要写明：每个字段能否取得、覆盖了多少比例的比赛、调用成本，以及现有 admin 快照能否补齐。

### 1.3 覆盖与清洗

- 统计必须说明覆盖范围。接口只能读到部分比赛时，显示「已记录场次」，不宣称为完整生涯。
- 隐藏资料、同步不足或字段缺失标记为「数据不足」，不等同于玩家没有绝活。
- 按比赛 ID 去重；未结束或没有有效胜负的比赛不计入胜率。

## 2. 熟练度与候选池

起始门槛：

- 已记录历史至少 50 场：进入正式绝活候选池。
- 最近 180 天至少 20 场：作为判断当前状态的样本起点。
- 长期场次足够但近期样本不足：仍可评估历史绝活。
- 未满历史门槛但近期表现突出：进入潜力候选，不直接认定为正式绝活。

不要求英雄占个人总场次的固定比例，也不要求使用次数排名靠前，否则会误伤英雄池深、总场次多的玩家。场次只证明熟练，不证明强。

**可选：学习期剔除。** 计算表现时剔除每个英雄最早的 N 场（初始 15～20，默认关闭，作为对照实验）。剔除只影响表现计算，不影响场次门槛。

## 3. 两条入选路径

### 路径 A：优势型

样本充分，玩这个英雄时比玩其他英雄更能赢或表现更好。

- **个人基准用「其他英雄」**：同一统计窗口内排除该英雄后的胜率，避免该英雄自身把基准拉高。
- 其他英雄样本不足（初始 < 50 场）时，个人基准不可靠，降级判断；单英雄玩家不能机械套用此路径。
- **胜率压缩提醒**：天梯匹配会让玩家总胜率趋近 50%，英雄间的胜率差也会被压缩。因此不要用固定的点估计差值做硬门槛，改用概率判断：

```text
P(英雄真实胜率 − 个人基准 > δ) ≥ 概率门槛
δ 初始 2～5 个百分点，概率门槛初始 0.8，均待校准
```

- 有 IMP 时，可以并行计算表现版优势：`该英雄收缩后平均 IMP − 其他英雄平均 IMP`，同样用区间下界判断。

示例：

| 个人基准胜率 | 英雄胜率      | 初步解释                     |
| ------------ | ------------- | ---------------------------- |
| 48%          | 56%           | 相对优势明显，值得进一步验证 |
| 59%          | 56%           | 不能仅凭胜率较高认定为优势型 |
| 50%          | 80%，仅 10 场 | 样本不足，先观察             |

### 路径 B：精通型

长期大量使用，并且相对于同英雄、同位置、同分段的其他玩家持续表现良好。即使没有明显高于个人平均，也可能是绝活。

为什么需要：一个玩家主要玩 6 个英雄，各有几百场、水平接近。这些英雄共同构成个人平均，优势型可能一个都选不出来。

为什么不能只靠胜率：在匹配机制下，玩家在稳定分段的胜率会趋近 50%，所以「胜率持续良好」很难成为独立证据。精通型必须依赖不受个人平均影响的外部表现基准。

**外部基准优先级：**

1. **Stratz IMP（首选）**：需先核实其定义，确认它是否已按英雄、位置、分段归一化。判定条件：场次达标，收缩后平均 IMP 的置信下界 > 0，且多个时段持续为正。
2. **OpenDota benchmarks 百分位（备选）**：只覆盖已解析的比赛，需说明覆盖率。百分位是对全体玩家计算的，高分段玩家玩什么都偏高，因此要和该玩家自己在其他英雄上的平均百分位对比，或只在同分段内比较。只与同英雄、同位置比较，不设全英雄统一阈值。
3. **两者都没有**：只标「高熟练候选」，不认定精通型绝活，并说明数据限制。

精通型的具体门槛在真实案例验证后确定，当前不假装已有可靠阈值。

## 4. 小样本处理与可信度

胜率收缩：

```text
修正胜率 = (胜场 + k × 基准胜率) / (场次 + k)
k 初始 30；基准胜率使用 0～1 的比例
```

IMP 等连续指标同理：

```text
修正均值 = (Σ指标 + k × 基准均值) / (场次 + k)，再用标准误算区间下界
```

注意事项：

- 收缩后的点估计不等于可信度。更严谨的做法是用 Beta-Binomial 等方法，估计「真实值超过基准至少 δ」的概率，并纳入基准本身的不确定性。
- 600 场 60% 应比 60 场 60% 有更强证据。不能按单一数字排序取前几名。
- **多重比较**：一个玩家要评估几十上百个英雄，总会有几个偶然达标。概率门槛要偏严；第二版可考虑做假发现率（FDR）控制。
- 对局并非完全独立，组排和版本集中会影响统计解释。
- 展示中区分原始胜率与修正胜率。

## 5. 分时段验证与版本影响

累计数据好看，不代表现在仍然强。至少要检查表现是否主要来自某一小段时期。

- 多个时间段都有良好表现：证据更强。
- 早期低分段连胜，升分后明显变差：区分历史能力与当前状态。
- 某版本短期特别强：避免把版本红利全部归因于个人。
- 大多数胜场来自固定组排：有数据时拆分观察，不直接断言被带。
- **英雄重做**：同一英雄 ID 在大改前后可视为不同阶段，跨重做的持续性单独看待。

不要求每个时间段都达标，以免过度惩罚正常波动。每段需要有足够样本，分段方式与稳定性阈值待校准。

有可靠的同分段版本统计时，可用辅助近似指标：

```text
个人英雄优势 ≈ 个人英雄胜率 − 个人基准胜率
               − (同分段该英雄胜率 − 同分段总体基准胜率)
```

这只是解释性近似，不能消除阵容、位置和选人偏差。数据不可靠时先省略版本修正。

**选人偏差提醒**：玩家往往在阵容有利时才选出绝活，这会让胜率偏高。第二版若能取得阵容预期胜率，可对比实际胜率与预期胜率。

## 6. 标签与展示

| 标签       | 含义                                                   |
| ---------- | ------------------------------------------------------ |
| 当前绝活   | 长期证据充分，近期样本与表现仍有支持                   |
| 历史绝活   | 历史证据明确，近期数据不足以确认当前状态               |
| 潜力绝活   | 近期表现突出，但累计证据不足                           |
| 高熟练候选 | 使用经验丰富，但缺少可靠外部基准或证据不足以确认精通型 |
| 常玩英雄   | 使用频繁，暂时没有明确的绝活证据                       |

- 当前/历史状态、优势型/精通型路径、近期上升/下降趋势分别存储，不要塞进一个互斥标签。
- 历史绝活近期下降时，保留历史身份，同时显示「近期状态下降」。
- 正式绝活与候选分开展示；没有达标者时允许空结果，说明「尚未识别出足够证据」。
- 排序可参考可信度、优势幅度和近期相关性，但不改变入选集合，不设数量上限。
- 展示可解释证据，不只显示一个不透明的分数：

> 帕克 · 中路 · 286 场 · 胜率 58% · 高于个人基准 7 个百分点 · 近半年 42 场 · 路径：优势型

（示例数据）建议附上入选路径、统计时间范围、数据覆盖说明与近期趋势。长期和近期指标混合显示时，必须分别标明范围。

## 7. 不建议直接作为硬门槛的指标

- 原始胜率：受小样本、版本、对局水平和匹配压缩影响。
- 总场次或使用排名：只反映常玩程度。
- 使用占比：会误伤英雄池深的玩家。
- 全英雄统一的 KDA、GPM、伤害阈值：偏向核心位、容易保命或特定机制的英雄；辅助在这些指标上天然吃亏。

KDA、经济、伤害等可以作为辅助证据，但要先确认定义与覆盖，并在同英雄、同位置、同分段内比较，不能用辅助数据掩盖样本不足。

## 8. 验证与验收

### 8.1 人工标注验证

挑选一批熟悉的玩家，**先独立记录**公认擅长的英雄，再看算法结果，避免看完结果再调整主观答案。玩家共识是参考，不是绝对真值。

### 8.2 时间外验证（可自动运行）

1. 选一个截止日 T，例如最近 6 个月之前。
2. 只用 T 之前的数据跑筛选，得到入选集合。
3. 用 T 之后的数据检验：入选英雄是否仍优于该玩家的其他英雄或外部基准，计算「保持率」。
4. 对照组：T 之前高场次但未入选的英雄，看它们在 T 之后的表现，确认入选与否确实有区分度。
5. 用保持率和区分度来调整 k、δ、概率门槛和场次门槛。

### 8.3 必测案例

- 单英雄专精，其他英雄样本不足。
- 6 个以上主力英雄，整体表现都不错。
- 常玩某英雄但胜率或表现一般。
- 十几场连胜导致极高胜率。
- 历史绝活长期未玩。
- 最近开始练的新英雄，表现正在上升。
- 升分前后表现变化明显。
- 固定队组排较多，或不同模式混合。
- 资料隐藏、对局记录不完整。
- 主玩辅助位的玩家（检查是否被经济类指标误伤）。

分别记录漏选与误选原因。重点检查：是否漏掉深英雄池玩家、是否把常玩误判为绝活、是否被短期连胜或历史低分段成绩主导。调参后用另一批玩家复验，避免只适配已有案例。

### 8.4 验收要求

- 不强制 Top N；没有证据时不凑数。
- 相对优势不是唯一入选路径。
- 数据不足不等于能力不足。
- 近期状态与历史实力能分别表达。
- 每个入选英雄都有可解释依据。

## 9. 落地范围

### 第一版

1. 盘点 DotaHub 现有数据来源与覆盖，填写第 1.2 节字段清单，重点确认 IMP、位置和分段能否取得。
2. 确定统计模式、时间范围与个人基准，完成去重与有效比赛筛选。
3. 建立不限数量的候选池，实现胜率收缩和优势型判定（其他英雄基准 + 概率判断）。
4. 加入分时段验证，区分长期证据与近期状态。
5. 精通型：有 IMP 或 benchmarks 时启用；否则展示「高熟练候选」并说明限制。
6. 输出入选原因、数据范围和可信度依据。
7. 实现时间外验证脚本，结合人工案例调参，再确定正式默认值。

### 第二版（可选）

- 阵容预期胜率对照，处理选人偏差。
- 冷门度标签：按全局选取率区分「冷门绝活」。
- 学习期剔除的对照实验结果决定是否默认开启。
- 组排拆分统计。
- 多重比较的 FDR 控制。

## 10. 集中配置的起始参数

| 参数               | 初始值             | 说明                |
| ------------------ | ------------------ | ------------------- |
| 历史最低场次       | 50                 | 进入正式候选池      |
| 近期窗口           | 180 天             | 判断当前状态        |
| 近期最低场次       | 20                 | 近期样本起点        |
| 胜率收缩强度 k     | 30                 | 待校准              |
| 连续指标收缩强度 k | 20                 | IMP 等，待校准      |
| 优势幅度 δ         | 2～5 个百分点      | 待校准              |
| 概率门槛           | 0.8                | 待校准              |
| 个人基准最低样本   | 其他英雄合计 50 场 | 不足则降级判断      |
| 学习期剔除 N       | 0（关闭）          | 对照实验可设 15～20 |
| 时间外验证检验集   | 最近 6 个月        | 用于调参            |

所有值都是起点，不是标准。
