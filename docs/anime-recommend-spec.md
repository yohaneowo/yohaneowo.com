# 随机动漫推荐功能：设计规格（基于 AniList + Bangumi + Trakt）

> Discord 指令 `/anime recommend`，动漫版的 `/movie recommend`（见 `movie-recommend-spec.md`）。
> 骨架沿用电影版：几个推荐池各自打分、加权随机抽取，再交给 Claude 挑一部并写理由；「想看」「看过了」写回 Trakt；每天 5 次，另有奖励次数。
> 跟电影版不同的是：推荐单位是**一季**（AniList 的一个条目），候选来自 **AniList**，口味直接用同步时已经建好的动漫资料，多了**续作**和**新番**两个池。
>
> 决定（2026-10-19）：
>
> - 写回 Trakt 用社群维护的动漫 ID 对照表（方案 A）；对不上的作品不显示「想看」「看过了」，只给链接。
> - 独立指令 `/anime recommend`，额度跟电影分开：动漫每天 5 次，加上每人 100 次一次性的奖励次数（2026-10-19 加）。
> - 有新番池，不设每日上限；网站「帐号设定」有开关决定推荐要不要包含新番，默认开启。指令里明确选了「只要新番」时以指令为准。

## 一、数据来源

| 用途                                         | 来源                                                                                                 |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 看过的动漫、每季评分、类型、标签、制作人员   | 同步时建好的快照 `snapshot.anime`（每季已有 AniList / Bangumi / MAL ID、分数、制作公司、监督等）     |
| 候选作品、类型、标签（含排名）、热门度、评分 | AniList GraphQL：`Media`、`Page.media`（按标签、类型、年代、播出季筛选）                             |
| 「看了这部的人也推荐」                       | AniList `Media.recommendations`（社群投票，按 `rating` 排序）                                        |
| 续作关系                                     | AniList `Media.relations`（`relationType: SEQUEL`）                                                  |
| 制作公司、监督的其他作品                     | AniList `Studio.media`、`Staff.staffMedia`（同人员卡，见 `credits.py`）                              |
| 本季新番                                     | AniList `Page.media(season, seasonYear, status: RELEASING)`                                          |
| 中文名、Bangumi 分数                         | Bangumi（同人员卡的配对与快取：原名配对，配不上再用片名加年份搜寻）                                  |
| MAL 分数                                     | MAL 官方 API（沿用同步的快取）                                                                       |
| AniList → TMDB 剧集 + 季数                   | 社群对照表 Fribb/anime-lists `anime-list-full.json`（`themoviedb_id.tv` / `.movie`、`season.tmdb`）  |
| TMDB → Trakt                                 | Trakt `GET /search/tmdb/{id}?type=show`（剧场版用 `type=movie`），结果永久快取                       |
| 想看列表、隐藏列表、写回                     | Trakt `/sync/watchlist`、`/users/hidden/recommendations?type=show`、`/sync/history`、`/sync/ratings` |

**对照表的覆盖率（2026-10-19 量测）：** AniList 最热门的 200 部（电视版、剧场版、网络版）全部对得上 TMDB，192 部有季数；本季最热门的 50 部有 43 部对得上，新番会落后一点，因为对照表大约每周更新。按类型：电视版 72%、OVA 60%、剧场版 39%、网络版 14%、特别篇 6%。

**对照表的使用方式：** 由 admin 每周下载一次存进快取（约 7.5 MB，只留 AniList ID → TMDB / 季数 的部分），不放进 repo。这份对照表没有声明授权条款，所以只在执行时取用。

## 二、推荐单位与排除规则

**单位是一季**（AniList 的一个条目：电视版的一季、一部剧场版、一部网络版）。特别篇和 MV 不推荐。

每次推荐前的排除集合：

1. **看过的**：快照里每季的 AniList ID（有观看记录的季）。
2. **Trakt 隐藏列表**里的剧（经对照表换算）。
3. **最近 30 天推荐过的**（本地记录）。
4. **还没开播的**。
5. **负向信号传播**：打低分的系列，同系列其他季和以它为种子的推荐结果都排除（同电影版 3.1）。

**想看列表不排除，反而加分**，卡片标注「已在你的想看列表」。

## 三、口味画像

类型、标签、制作公司、监督这些要向 AniList 查（每分钟约 30 次的限制），同步时已经查好存进快照，所以口味直接用快照，不再重查。电影版从 Trakt 现抓名单是对的（较新、有想看和隐藏名单），动漫版只把「想看」「隐藏」和「名单有没有变动」照电影版向 Trakt 现抓：

- **新鲜度**：推荐池快取一天；每次推荐先问 Trakt `last_activities`，名单变了就重建（同电影版）。
- **刚看过的**：bot 里按「看过了」后，立刻把那一季加进排除名单，并请 admin 排一次同步，不必等同步完成。

口味的算法：

- **每季权重**：同电影版（以个人均分为中心，评分高的正、低的负；没评分的看完整季算小幅正向）。
- **类型向量**：AniList 的 18 个类型，按权重加总后正规化。
- **标签向量**：AniList 标签带排名（0–100），只用排名 ≥ 60 的，权重乘以排名比例。
- **偏爱的制作公司、监督**：沿用观影页「偏爱」的算法（至少两部、平均比个人均分高 0.3）。
- **盲区**：很少碰的类型和标签（对比 `genre-weights.ts` 的动漫基率），以及很少看的年代。

## 四、推荐池

| 池     | 内容                                                                                | 打分重点                         |
| ------ | ----------------------------------------------------------------------------------- | -------------------------------- |
| 续作   | 看完而且评分 ≥ 个人均分的系列，下一季还没看的（顺着 `SEQUEL` 关系找第一个没看的季） | 前作评分、续作本身的分数         |
| 舒适圈 | 高分作品的 AniList「相关推荐」，加上偏爱的制作公司、监督的其他作品                  | 跟口味向量的相似度、贝叶斯平均分 |
| 跨界   | 盲区类型或标签，但出自偏爱的制作公司或监督                                          | 盲区程度 × 人员偏爱程度          |
| 探索   | 盲区类型、标签、年代里评价最高的经典（热门度门槛避免冷门）                          | 贝叶斯平均分、盲区程度           |
| 新番   | 本季正在播、跟口味相似的作品（受网站开关控制）                                      | 口味相似度、目前分数、热门度     |

- 各池先打分，再用 softmax（温度同电影版）抽样；池之间的比例沿用电影版的小型 bandit：「想看」算正向、「换一部」算负向，所以常被跳过的池会自然少被抽中。
- **续作**只推「下一季」，不推中间跳过的季；一个系列同时只会出现一季。
- **新番**不设每日上限；网站开关关闭时整个池不建，除非指令明确选了「只要新番」。
- 抽出候选后，同电影版交给 Claude（`claude-sonnet-5-5`）从约 12 部里挑一部并写理由；超时就用加权随机的结果。

## 五、指令与卡片

### `/anime recommend`

筛选选项：

- **类型**：AniList 的 18 个类型（中文显示）。
- **年代**：1980 年代到 2020 年代。
- **形式**：电视版、剧场版、网络版。
- **长度**：一季内（≤ 13 集）、两季（14–26 集）、长篇（> 26 集）。
- **只要新番**：只从新番池抽（不受网站开关影响）。

### 卡片

- 中文名（Bangumi，没有就用原名）、AniList 封面、年份与播出季、集数、播出状态。
- Bangumi / MAL 分数，制作公司，几个代表标签。
- 推荐理由（AI 或模板），以及「属于哪个池」的小标记（续作、新番等）。
- 链接：Bangumi、AniList、MAL；对得上 Trakt 时也给 Trakt。

### 按钮

| 按钮      | 行为                                                                                                |
| --------- | --------------------------------------------------------------------------------------------------- |
| 想看      | 把这一季加进 Trakt 想看列表（剧集带季数；剧场版加电影）                                             |
| 看过了    | 先查 Trakt 有没有评分；没有就让用户选 1–10 分（可取消），写入评分和整季的观看记录；评分退还这次额度 |
| 删除评分  | 撤销评分和刚写入的观看记录，收回退还的额度                                                          |
| 换一部    | 用掉一次额度，抽下一部                                                                              |
| AI 怎么看 | 同电影版                                                                                            |

**对不上 Trakt 的作品**（对照表没有，或 Trakt 找不到）不显示「想看」「看过了」，只给链接。

**写回的单位**（2026-10-19 实测热门续作后定案）：对照表给 TMDB 的剧、季数和集数偏移（`episode_offset.tmdb`），再用 Trakt 该季的集数判断：

| 情况                                   | 例子                                                                                  | 写回                                                                                               |
| -------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| AniList 集数 = Trakt 该季集数          | 多数作品                                                                              | 整季（想看、观看记录、评分）                                                                       |
| Trakt 那一季比较大，偏移加集数放得进去 | 进击的巨人第三季 Part 2 是 Trakt 第三季的第 13–22 集；咒术回战在 Trakt 第一季有 59 集 | 想看加整季；观看记录只写那几集；评分写在整季（分割季的两部分共用一个季评分，跟观影统计的处理一致） |
| 还在播、集数未定                       | 本季新番                                                                              | 只有想看                                                                                           |
| 对不上（没有季数、集数放不下）         | 火影忍者疾风传                                                                        | 不显示 Trakt 按钮，只给链接                                                                        |

**整部作品的评分**（2026-10-19 决定）：Trakt 的整部评分跟各季评分是分开的。透过 bot 写入或删除季评分后，整部评分自动设为这部在 Trakt 上**所有季**评分的平均（不含第 0 季特别篇），四舍五入成整数（7.5 → 8）。整部原本有分数也照样覆盖，但第一次覆盖前的分数会记在 admin 快取（`anime_show_rating_origin`）；之后季评分全被删光时还原那个分数，原本没有就删掉整部评分。只有透过 bot 评分时才会触发，不会去改 Trakt 上其他作品。

剧场版写成 Trakt 的电影（经 `/search/tmdb/{id}?type=movie`）。「删除评分」移除评分，并撤掉这次写入的观看记录（整季、那几集，或电影的那一次）；因为推荐只挑没看过的季，这些观看记录都来自这次推荐。

## 六、额度与资料储存

- **额度**：每天 5 次（第一次 + 四次「换一部」），台北时间半夜重置；评分退还每天最多 3 次。跟电影版各自独立。
- **奖励次数**：每人一开始有 100 次（`movie_subscriber.anime_bonus_picks`，默认 100），不会每天重置。当天的 5 次用完才用奖励次数（那次推荐记 `uses_bonus`）；用奖励次数抽到的那部评分退还时，退回奖励次数。卡片下方显示「今天还能换 X 次，另有 Y 次奖励次数」。
- **加奖励次数**：站长专用的 `/anime-bonus user amount`（负数是扣回，最低到 0）。伺服器里只有管理员看得到，执行时再核对是不是 bot 应用的拥有者（或团队成员）；呼叫 admin `POST /internal/movies/anime-picks/{discord_id}/bonus`。
- **推荐记录**：新表 `bot_anime_pick`（AniList ID、TMDB ID、季数、Trakt ID、池、评分、写回的 history ID、退还标记），结构比照 `bot_movie_pick`。
- **新番开关**：存在 admin 的观影档案（`movie_subscriber.anime_airing`，默认 `true`）。网站「帐号设定」透过 admin 的接口读写，跟评分来源偏好存在网站资料库不同，因为推荐在 admin 里跑。
- **测试帐号额度**：沿用 `pick_quota` 的做法，动漫额度另设一个栏位（`anime_pick_quota`，取代每天的 5 次）。

## 七、整体流程

1. bot 收到 `/anime recommend` → 呼叫 admin `POST /internal/movies/anime-picks`（带 Discord ID 和筛选）。
2. admin 读观影档案和快照；没有 Trakt token 回 403（同电影版）。
3. 推荐池第一次请求时建好，快取一天；快照更新（同步完成）就重建。各阶段写进进度快取，bot 显示「正在…」。
4. 抽候选 → Claude 挑选 → 组卡片（中文名、分数、Trakt 对照）→ 写一笔 `bot_anime_pick`。
5. 按钮回到 admin 对应的 `want` / `watched` / `unrate` / `skip`。

---

## 八、实作顺序

1. **admin 引擎**：对照表下载与快取、口味画像、五个推荐池、抽样、AI 挑选、`bot_anime_pick`、接口；测试照电影版的方式写。
2. **Trakt 写回**：季数验证、想看、看过了、删除评分。
3. **bot 指令**：`/anime recommend`、卡片、按钮、进度讯息；部署后重新注册测试 bot 的指令。
4. **网站设定**：帐号设定页加「动漫推荐包含新番」开关，加 admin 读写接口。
5. dev 测试后，整批跟其他功能一起上线。

## 九、风险

- **对照表落后**：新番开播后约一周才进对照表，这段时间新番卡片没有 Trakt 按钮。
- **季数不一致**：少数作品 AniList 分季方式跟 TMDB 不同（例如分割季合并成一季），写回时可能写到错的季。实作时先验证，对不上的宁可不显示按钮。
- **AniList 速率**：每分钟约 30 次，跟同步和人员卡共用。推荐池要快取，建池时限制请求数。
- **对照表没有授权条款**：只在执行时下载使用，不放进 repo；如果之后出问题，改成用 Trakt 以片名加年份搜寻作为退路。
