# Dota 绝活英雄筛选方案（交接给 Claude）

日期：2026-10-21。状态：讨论方案，尚未实现或用真实玩家数据校准。

## 需求与核心结论

识别一个玩家真正擅长的英雄，数量不限定为 1～3 个。满足条件的全部展示，可以有 8～9 个，也可以暂时没有；不能为了展示效果凑数。

绝活需要结合熟练度、表现与证据可信度判断。常玩不等于绝活，最近没玩也不代表历史上不擅长。筛选是否入选与入选后的展示排序是两个问题，不要用 Top N 代替筛选。

本方案建议采用「优势型／精通型双路径 + 分时段验证 + 当前／历史标签」。下面的数值都是待验证的起始参数，不是公认标准，也不应直接当成最终产品规则。

## 1. 数据范围与可比性

尽量比较同一时期、同一模式、相近分段的数据。有位置资料时进一步按位置比较。不同模式应分开，避免把娱乐模式与天梯混为一谈。

需要的基础资料包括英雄、比赛时间、胜负、模式；分段、位置、组队情况和对局表现属于增强资料。实际能否取得、历史覆盖是否完整，应先检查现有数据链路。

统计必须说明覆盖范围。接口只能读到部分比赛时，显示「已记录场次」，不能宣称为完整生涯。隐藏资料、同步不足或字段缺失应标记为数据不足，不等同于玩家没有绝活。按比赛 ID 去重，未结束或没有有效胜负的比赛不计入胜率。

## 2. 熟练度与候选池

建议初始门槛：

- 生涯或已记录历史至少 50 场：进入正式绝活候选池。
- 最近 180 天至少 20 场：作为判断当前状态是否有足够样本的起点。
- 长期场次足够但近期样本不足：仍可评估历史绝活。
- 未满历史门槛但近期表现突出：进入潜力候选，不直接认定正式绝活。

不要要求英雄占个人总场次的 10%，也不要要求使用次数排前三。这些限制会误伤英雄池深、总场次多的玩家。

场次只证明接触与熟练程度，不证明强。几百场低效表现也不能仅凭场次入选。

## 3. 两条入选路径

### 路径 A：优势型

样本充分，使用这个英雄时比使用其他英雄更能赢。

优先使用同一统计窗口中「其他英雄」的胜率作为个人基准，避免该英雄自身把基准拉高。其他英雄样本太少时，个人基准不可靠，需要降级判断；单英雄玩家尤其不能机械套用相对优势规则。

示例：

| 个人基准胜率 | 英雄胜率      | 初步解释                     |
| ------------ | ------------- | ---------------------------- |
| 48%          | 56%           | 相对优势明显，值得进一步验证 |
| 59%          | 56%           | 不能仅凭胜率较高认定为优势型 |
| 50%          | 80%，仅 10 场 | 样本不足，先观察             |

可从「修正胜率高于个人基准 3～5 个百分点」开始校准，但不能把它作为所有绝活必须满足的条件。

### 路径 B：精通型

长期大量使用，在相近水平对局中持续表现良好，即使没有明显超过个人平均，也可能是绝活。

必要性：一个玩家主要玩 6 个英雄，各有几百场、胜率都在 56% 左右。这些英雄共同撑起个人平均，要求每个高于个人平均 3～5 个百分点，可能一个都选不出来。

这条路径需要独立于个人平均的支持，例如同英雄、同分段、同位置的表现基准，以及多个时期持续良好的表现。精通型的具体场次与表现门槛应在真实案例验证后确定，当前不假装已有可靠阈值。

如果只有场次和胜负，且缺少可信的外部比较基准，只能先标为「高熟练候选」，不能仅凭场次认定精通型绝活。第一版可以先完整实现优势型，对精通型明确保留数据不足状态。

## 4. 小样本处理与可信度

易于实现的胜率收缩方法：

```text
修正胜率 = (胜场 + k × 基准胜率) / (场次 + k)
k 初始可取 30
```

基准胜率使用 0～1 的比例。k 相当于加入若干场基准表现，样本少时更保守，样本多时更接近原始胜率。k 需要校准，展示中应区分原始胜率与算法使用的修正胜率。

注意：收缩后的点估计不等于统计可信度。更严谨的版本可以用 Beta-Binomial 等方法，估计「英雄真实胜率超过基准至少 3 个百分点」的概率，并将基准本身的不确定性纳入考虑。先验、概率门槛和优势幅度都需要验证。

600 场 60% 应比 60 场 60% 有更强证据。不能只按胜率或收缩后的单一数字排序后取前几名。对局之间也并非完全独立，组排与版本集中会影响统计解释。

## 5. 分时段验证与版本影响

累计胜率好看，不代表现在仍然强。至少要检查表现是否主要来自某一小段时期。

- 多个时间段都有良好表现：证据更强。
- 早期低分段连胜，升分后明显变差：区分历史能力与当前状态。
- 某版本短期特别强：避免把版本红利全部归因于个人熟练度。
- 大多数胜场来自固定强力队友组排：有数据时拆分观察，不能直接断言是被带赢。

不要要求每个时间段都达标，否则会过度惩罚正常波动。可以按时间窗口或连续比赛分段，但每段要有足够样本；分段方式和稳定性阈值待校准。

有可靠同分段版本统计时，可考虑一个辅助近似指标：

```text
个人英雄优势 ≈ 个人英雄胜率 − 个人基准胜率
               −（同分段该英雄胜率 − 同分段总体基准胜率）
```

这只是解释性近似，不是已验证的因果模型，不能消除阵容、位置和选人偏差。各项需要来自可比的时期与模式。数据不可靠时先省略版本修正，不要凭空假设。

## 6. 标签与展示

| 标签       | 含义                                     |
| ---------- | ---------------------------------------- |
| 当前绝活   | 长期证据充分，近期样本与表现仍有支持     |
| 历史绝活   | 历史证据明确，近期数据不足以确认当前状态 |
| 潜力绝活   | 近期表现突出，但累计证据不足             |
| 高熟练候选 | 使用经验丰富，但尚不足以确认精通型       |
| 常玩英雄   | 使用频繁，暂时没有明确的绝活证据         |

当前／历史状态、优势型／精通型路径、近期上升／下降趋势应分别存储，避免将不同维度塞成一个互斥标签。历史绝活近期表现下降时保留历史身份，同时显示「近期状态下降」，不要误标成只是近期没数据。

正式绝活与候选区分开展示；没有达标者时允许空结果，解释是尚未识别出足够证据。排序可以参考可信度、优势幅度和近期相关性，但不改变入选集合，不设置数量上限。

展示可解释证据，例如：

> 帕克 · 286 场 · 胜率 58% · 高于个人基准 7 个百分点 · 近半年 42 场

以上仅为示例数据。建议附上入选路径、统计时间范围、数据覆盖说明与近期趋势。避免仅展示一个不透明的「绝活分 92」。若长期和近期指标混合显示，必须分别标明范围。

## 7. 不建议直接作为硬门槛的指标

- 原始胜率：容易受到小样本、版本与对局水平影响。
- 总场次或使用排名：只能反映常玩程度。
- 使用占比：会误伤英雄池深的玩家。
- 全英雄统一 KDA、GPM、伤害阈值：会偏向核心、容易保命或特定机制的英雄。

KDA、经济、伤害、IMP 等可以作为辅助证据，但应先确认其定义与覆盖，并尽量在同英雄、同位置、同分段内比较。不能因为有指标就强行纳入总分，也不能用辅助数据掩盖样本不足。

## 8. 第一版落地范围

1. 检查现有 DotaHub 数据来源与覆盖，确认能获取哪些字段。
2. 明确统计模式、时间范围与个人基准，完成去重与有效比赛筛选。
3. 建立不限制数量的候选池，进行胜率收缩和优势型判定。
4. 加入分时段验证，区分长期证据与近期状态。
5. 有可靠比较数据时启用精通型；否则展示高熟练候选并说明限制。
6. 输出入选原因、数据范围和可信度依据，而不只是单一得分。
7. 用真实玩家案例调整参数，再确定正式默认值。

可集中配置的起始参数包括历史最低场次 50、近期窗口 180 天、近期最低场次 20、收缩强度 30、相对优势幅度 3～5 个百分点。不要把这些初始值散落在实现中，也不要把它们描述为已经验证的标准。

## 9. 验证与验收

挑选一批熟悉的玩家，先独立记录公认擅长英雄，再看算法结果，避免看完结果才调整主观答案。玩家共识也是参考，不是绝对真值。

至少覆盖以下案例：

- 单英雄专精，其他英雄样本不足。
- 6 个以上主力英雄，整体胜率都不错。
- 常玩某英雄但胜率或表现一般。
- 十几场连胜导致极高胜率。
- 历史绝活长期未玩。
- 最近开始练的新英雄，表现正在上升。
- 升分前后表现变化明显。
- 固定队组排较多，或不同模式混合。
- 资料隐藏、对局记录不完整。

分别记录漏选与误选原因，重点检查是否漏掉深英雄池玩家、是否将常玩误判为绝活、是否被短期连胜或历史低分段成绩主导。调参后用另一批玩家验证，避免只适配已有案例。

验收要求：不强制 Top N；没有证据时不凑数；相对优势不是唯一入选路径；数据不足不等于能力不足；近期状态与历史实力能够分别表达；每个入选英雄都有可解释依据。
